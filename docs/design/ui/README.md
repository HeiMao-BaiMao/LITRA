# LITRA UIデザイン案

HTML/CSS/JSで動作する対話可能な画面案です。主画面・分離パネルに加え、作品資料とジャンル研究の画面設計を設定済みの `@designer`（SWE2）へ依頼し、共有状態と操作を統合しています。**既存のRust/WASM/Tauri製品UIを置き換えたものではありません。**

## 開く

リポジトリのルートで実行します。

```sh
python3 docs/design/ui/serve.py --port 4175
```

- [主画面](http://127.0.0.1:4175/main.html)
- [人物資料](http://127.0.0.1:4175/main.html?view=characters)
- [ジャンルライブラリ](http://127.0.0.1:4175/genres.html)

`file://` ではなくlocalhostで配信します。このサーバーはloopback限定・キャッシュ無効です。外部フォント、CDN、AI API、資格情報にはアクセスしません。

## 操作できる範囲

- 画面案専用の作品・エピソード管理、本文・要約・一行要約・話別メモの編集。
- 人物・世界観の全既存項目とカスタム項目、全体／話別の人物関係、作品全体のプロジェクトメモ。
- ジャンル概要、原資料の登録・本文参照・メタデータ編集・削除、分析対象と分析結果の表示例。
- 手動知識の管理、候補の採用・保留・却下。原資料、未承認候補、採用済み知識を区別。
- ジャンル専用会話のスレッド管理・下書き・添付。作品チャットとは別の状態。
- チャット、要約、話別メモ、作品設定資料、プロジェクトメモの5対象を分離・再結合。ジャンルライブラリと専用会話も独立ウィンドウ。

生成・分析・AI送信は未接続表示で、架空の成功結果を作りません。会話や分析の初期データは表示例です。既存機能との対応と実際の確認範囲は [機能・状態・分離の対応表](feature-coverage.md) に記載しています。

## データとウィンドウ

- 専用IndexedDB `litra-ui-design-review-v2` に保存します。実作品ファイル・製品の保存領域とは別です。ブラウザのデータ削除で消えます。
- SharedWorkerが更新を直列化し、IndexedDBのコミット後に画面へ反映します。保存失敗をメモリー保存の成功に置き換えません。
- 自動保存は入力時の作品・話・項目IDを保持します。作品切替後の遅延保存が別作品へ書き込まない構造です。
- 分離前に入力を確定し、接続先の準備完了まで元画面を残します。選択中の作品・話・資料・スレッドを共有し、入力位置・スクロール位置は対象別に保持します。
- 主画面を閉じても分離側は操作できます。全画面終了後は保存データを読み直し、前回の別窓をボタンから一つずつ復元できます。
- ポップアップ拒否時は元の編集画面を残します。別タブになる場合も同じ画面を利用します。位置・サイズはブラウザが許す範囲で、OSウィンドウと同一の配置は保証しません。
- SharedWorkerまたはIndexedDBが利用できない場合は理由を表示します。別々のローカル状態へ黙って分岐しません。

「画面案データを書き出す」は確認用JSONの出力です。製品の作品ファイル形式への保存・復元ではありません。配信ポートが違えばブラウザの保存領域も別になります。

## ファイルの責務

| ファイル | 責務 |
|---|---|
| `main.html` / `panels.html` / `genres.html` | 主画面・対象ごとの分離画面・ジャンル研究 |
| `references.js` / `genres.js` | 資料と研究のフォーム・一覧・操作 |
| `app.js` | 作品・話の選択、本文等の編集、画面の統合 |
| `design-model.js` | 画面案データと更新コマンド |
| `design-worker.js` / `design-client.js` | 保存の単一所有者と画面間通信 |
| `design-windows.js` / `view-utils.js` | 分離・再結合・復元、フォームの入力位置保持 |

これらは画面案専用で、製品のAppRuntime/AppClientやWASMコアではありません。製品側の境界は [ブラウザ共通UI・WASM対応アーキテクチャ](../browser-ui-architecture.md) を参照してください。

## 実施した確認

Firefoxの実画面で確認しています。

- 人物名の編集、作品切替直前の別名編集が元作品にだけ保存されること。
- 第3話だけの関係を追加し、人物A/B・方向・説明を保存しても全体の関係が変わらないこと。
- プロジェクトメモの作成・編集が話別メモを変更せず、主画面終了後も編集できること。
- 原資料の登録、セグメント付き本文参照、候補の保留→採用と承認区分・出典の保持。
- ジャンル会話の新規スレッド、既存下書きの保持、名前付きテキスト添付と原資料の独立性。
- 5対象の分離、資料の再結合時の選択範囲・カーソル復帰、全画面終了後のデータ保持と別窓の手動復元。
- 主画面1440px幅、ジャンル画面1200px幅、主画面とジャンル画面390px幅。390px幅で文書の横はみ出しがないこと。

一時的なNodeスクリプトで、作品・話の分離、古いrevisionの拒否、関係の範囲、候補採用の冪等性と権限、Unicodeを含む資料のオフセットも確認しました。確認は全機能の網羅試験ではありません。

実AI、WASMによる執筆・ツール実行、既存作品の入出力、OAuth、OS資格情報、WebDAV、TauriのウィンドウAPIは未接続です。ポップアップ拒否、IME実機入力、ストレージ障害注入、全ブラウザ互換性も未検証です。
