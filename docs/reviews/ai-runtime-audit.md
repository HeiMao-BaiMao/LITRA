# AI 実行経路の監査・修正

対象: v2.1.3 / `f821e70` を起点にしたローカル変更。

## 監査した経路

- メインチャット / ジャンルチャットのプロンプト、ツール一覧、ツール実行と継続
- 本文生成・整合性検査・取り込み分類・ジャンル資料の参照データ
- OpenAI Chat / Responses、Anthropic、Gemini のストリーム解析
- Codex / Copilot の OAuth 開始・中止・資格情報保存
- 開発用 AGENTS.md、CI、テスト、および Skill の所在

## 主な変更

1. モデルが返したツール名と引数を、実際に提示した一覧とスキーマに照合する。モードで隠したツールは実行しない。必須項目、未知フィールド、型、配列サイズ、数値下限、列挙値を実行前に検査する。
2. HTTP 通信がないツール待機中の停止も記録し、停止された実行が次のツールやラウンドへ進まないようにする。空の応答だけで「本文を編集しました」と表示しない。
3. ジャンルチャットの空送信と、スレッド作成・保存待機中の二重送信を防ぐ。連携設定の読み込み中に共有状態の借用を保持しない。
4. 参照データの囲みを共通化し、大文字・小文字・空白を含む境界タグ、属性名への割り込みを処理する。資料の内容と作者の依頼を区別する。これはモデルへの指示であり、権限制御の代替ではない。
5. ストリームのツール ID、エラー、途中切断と完了通知を整合させる。途中のツール引数を成功した空オブジェクトとして扱わない。
6. 登場人物・世界観の更新ではレコード ID の変更を拒否する。同じ ID の再送と任意の拡張フィールドは維持し、関係データの参照を守る。
7. OAuth の試行ごとに中止状態を分離し、古い試行が新しい開始によって復活しないようにする。資格情報は新しい全チャンクを保存した後で参照先を切り替え、保存失敗で以前の情報を壊さない。

## Skill の位置づけ

実行時に Skill を発見・ロード・実行する機構は、この起点のコードにはない。既存の `skills` は登場人物の能力フィールドである。開発用 Skill を `.agents/skills/` に追加し、既存のプロンプト・接続・ツール経路を安全に変更する手順を整理した。実行時 Skill 機構の新設は行っていない。

```sh
cargo test --locked --manifest-path frontend-rs/Cargo.toml
cargo check --locked --manifest-path frontend-rs/Cargo.toml --target wasm32-unknown-unknown
cargo build --locked --manifest-path frontend-rs/Cargo.toml --target wasm32-unknown-unknown --release
```

- 実サービスの API キーやユーザーデータは使用せず、テスト入力と mock で検証する。
- Linux コンテナには GLib / GTK / WebKitGTK がなく、Tauri 全体のテストは起動前の依存ビルドで停止する。ヘッドレス試験は変更対象の一部を検査する補完であり、Tauri 全体・OS 資格情報ストア・実 OAuth・UI の合格を意味しない。
- 実ブラウザ認証、各実プロバイダーへの接続、Windows インストーラ、マルチウィンドウ UI 操作は未検証。
- 参照データの区切りやプロンプト文言だけで、モデルのプロンプトインジェクション耐性を保証しない。今回のツール検証は一覧・引数の境界であり、自然言語の依頼の意味を認可エンジンとして判定するものではない。

## 今回残した課題

- `frontend-rs/src/windows/main_app/prompt_context.rs` の小さいモデル向け予算には最小文字数の下限があり、本文・設定・履歴を合計したトークン上限を保証していない。実測トークン数を使う全体予算管理は別途必要。
- `src-tauri/src/context/token_budget.rs` の履歴圧縮には、保存対象が全部予算内の場合の分割位置と最低メッセージ数に問題がある。ただし今回、実際の frontend AI 経路からの利用は確認できなかったため未変更。
- ウィンドウ・プロジェクト切替や編集中の並行操作について、実デスクトップでの回帰検証は残る。停止前に完了した保存は停止操作で巻き戻さない。
- JSON Schema 検証は現在のアプリ定義で使う部分集合に対応する。将来 `anyOf` / `oneOf` / nullable な型配列などを定義に導入する場合、検証器も先に拡張する。

- OAuth 保存形式は `chunks:v2` を使用する。新コードは旧 raw/v1 データを読めるが、旧版へ戻す場合は OAuth の再ログインが必要になることがある。
- `frontend-rs/src/windows/main_app/settings/oauth_ui.rs` の認証待ち中のプロバイダー切替では、古い非同期応答が表示に反映される可能性があり、UI 側の試行識別と実機試験が残る。バックエンドの認証試行と保存の競合修正とは別の課題。
